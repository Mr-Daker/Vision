# V002 — Capability and Evidence-Claim Matrix

**Status:** Ready for owner approval
**Roadmap task:** V002 (Foundation) · **Prerequisites:** V001 · **Owner:** Product + AI
**Companion documents:** [V001 scope](V001-scope-and-release-boundaries.md) · [V003 domain and lifecycle contracts](V003-domain-and-lifecycle-contracts.md)

> This matrix classifies every claim Vision may make. "Hackathon target" describes the bounded target; "Current implementation state" is maintained as roadmap work is verified. A completed internal workflow does not upgrade a simulated identity, recipient, or source into a real external integration.

**Revision note (this version):** aligned with domain contract 3.0.0 and verified implementation through V035: matching is owned by `IssueMatch`; evidence correction uses `IssueEvidenceLink`; participation is counted across the active issue-alias closure; identity is split into restricted `IdentityMapping`, stable `Participant`, and revocable `Session`; optional voice processing is disclosed as a separate Gemini transcription operation; rows 17 and 19 record the demo-scoped resolution workflow; and row 23 bounds the locked Marathi/English accessibility claim.

## Legend

- **Real** — the underlying signal is genuinely captured/computed; only its _interpretation_ is bounded by the "must not claim" column.
- **Simulated** — the hackathon build uses a fixture, stub, or internal-only actor standing in for an external system or verified identity.
- **Proposed** — the capability is planned and its output will be shown, but it is a system _proposal_ requiring review, not an established fact.
- **Unsupported** — no roadmap task claims this capability; it must never appear as a system assertion.

## Explicit prohibitions

Regardless of any wording elsewhere in the product, Vision must never:

1. Claim perfect AI-image detection (row 7).
2. Treat missing metadata as evidence of fraud (row 9).
3. Treat GPS/browser location as proof of physical presence (rows 3, 4).
4. Treat identity verification as evidence that a report's content is true (rows 1, 19).
5. Count repeated evidence from one person as independent corroboration (row 13).
6. Present an estimated population as verified affected citizens (row 14).
7. Present internal workflow events as government acknowledgment (row 16).
8. Present a staff resolution claim as a confirmed repair (row 17).
9. Present an uncalibrated model score as a probability of truth (rows 8, 10, 11).

Any UI copy, notification, demo narration, or presentation slide that violates one of these nine prohibitions is a defect against this document, regardless of which roadmap task introduced it.
